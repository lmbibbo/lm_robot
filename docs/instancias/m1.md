# Instancia M1

Variante de `LmRobot` pensada para operar en M1: fija la señal, el RSI y las
barras en M1 sin depender del timeframe del gráfico, pero ancla la referencia de
volatilidad en H1 para que el stop no se encoja con el ruido de un minuto.
Comparte todo el motor con `EA/LmRobot-H1.mq5`: no hay una copia de
`Include/LmRobot`.

## Archivos

| Archivo | Rol |
|---|---|
| `EA/LmRobot-H1.mq5` | Referencia H1/R11. Sus defaults no cambian. |
| `EA/LmRobot-M1.mq5` | Instancia M1: TF de señal y perfil de riesgo propios. |
| `Include/LmRobot/**` | Motor único compartido por las dos instancias. |

## Compilar

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\build.ps1 -Source EA\LmRobot-M1.mq5
```

Salida esperada: `EA/LmRobot-M1.ex5` y `0 error(es), 0 warning(s)`.

## Diferencias con la referencia

| Aspecto | `LmRobot-H1.mq5` | `LmRobot-M1.mq5` |
|---|---|---|
| TF de señal/RSI/barras | TF del gráfico | Input `SignalTimeframe`, por defecto `PERIOD_M1` |
| TF del ATR | `PERIOD_CURRENT` = TF del gráfico | `PERIOD_H1` (referencia estable) |
| Etiqueta del backtest | TF del gráfico | `SignalTimeframe` (M1) |
| `MagicNumber` | `202611030` | `202611040` |
| Prefijo de log | `LmRobot:` | `LmRobot-M1:` |
| Perfil de riesgo | R11 (agresivo) | Perfil M1 conservador (tabla siguiente) |
| Espera de reentrada | 0 s (sin espera) | `EntryCooldownSeconds=1800` |

## Perfil M1

El perfil no sale de una corrida M1, sino de aplicar a M1 las conclusiones de la
auditoría out-of-sample de R11 (`reportes/mt5/R12_Q4_analisis.md`): con `RiskPct=4`
y 19 pasos de grid la cuenta llegó a `−91,4 %` y al stop-out del bróker.

### Mercado y volatilidad

| Input | Valor M1 | Motivo |
|---|---|---|
| `SignalTimeframe` | `PERIOD_M1` | La señal se evalúa en M1 aunque el EA viva en un gráfico H1. |
| `AtrTimeframe` | `PERIOD_H1` | El ATR de M1 mide ruido; el de H1 describe el régimen real. |
| `MaxSpreadPips` | `3.0` | Con `TpPips=8` un spread de 10+ pips se come el objetivo. |
| `MaxAtrPips` | `15.0` | Filtra entradas en régimen H1 excepcional (noticias, rollover). |
| `AtrSlMultiplier` | `1.667` | Igual que la referencia. |

Con `MaxAtrPips=15` y `AtrSlMultiplier=1.667`, el SL derivado del ATR nunca pasa
de `15 × 1.667 ≈ 25` pips. Como `SlPips=30`, la distancia efectiva es
**siempre 30 pips** mientras el filtro permita entrar. Esto evita el absurdo de
R11: un SL nominal de 1.000 pips que no protegía nada.

### Riesgo y rejilla

| Input | Valor M1 | Motivo |
|---|---|---|
| `RiskMode` | `AUTO` | Mantiene el ajuste por volatilidad relativa. |
| `RiskPct` | `1.0` | Base recomendada por R12 (1,0–2,0). |
| `AutoRiskMaxPct` | `2.0` | Techo real del riesgo automático para M1. |
| `MaxBasketLossPct` | `20.0` | Cortacircuitos real de canasta (R12: 20–30). |
| `DailyLossLimitPct` | `6.0` | Cortacircuitos diario (R12: 5–10). |
| `MaxGridSteps` | `8` | R12: 8–10. |
| `LotMultiplier` | `1.4` | Menos agresivo que 1.667. |
| `MaxLotPerOrder` | `1.0` | R12: 1,0–2,0. |
| `MaxVolumePerStrategy` | `2.0` | R12: 1,0–2,0. |
| `SlPips` | `30.0` | 3,75× `GridStepPips`; coherente con la rejilla. |
| `TpPips` | `8.0` | Igual que la referencia; el objetivo sigue siendo corto. |
| `GridStepPips` | `8.0` | Un paso por movimiento típico de M1. |
| `MaxAggregateLossPct` | `30.0` | R12: 30–50, lado conservador. |
| `MaxAggregateVolume` | `4.0` | Tres estrategias con canastas de 2 lotes no caben; 4 lotes acota. |
| `UseSessionFilter` | `true` | Evita horas muertas y el rollover. |
| `SessionStartHour` / `SessionEndHour` | `8` / `17` | Sesión líquida en hora del servidor. |

Con estos topes, una canasta llena (`2,0` lotes × `30` pips) proyecta del orden de
`4–6 %` del balance, por debajo del 20 % de canasta y del 30 % agregado. Los
límites existen como red, no como freno normal: si el freno normal es el SL, el
límite sólo actúa ante un hueco o un fallo de ejecución.

### Cadencia: `EntryCooldownSeconds`

M1 genera ~60× más barras que H1. Sin control, el motor puede reabrir una canasta
apenas cierra, multiplicando comisiones, spread y exposición. La instancia M1 usa
una espera **por canasta/estrategia** después de cada cierre:

- `EntryCooldownSeconds = 1800` (30 minutos).
- Se cuenta desde el cierre detectado, no desde la última orden.
- `0` desactiva la espera.
- En `Strategy=ALL` cada slot tiene su propio reloj, así que las tres estrategias
  pueden escalonar entradas.

Implementación en el motor compartido: `CStrategySlot::lastCloseTime`,
`LmEntryCooldownElapsed()` y el campo `RuntimeConfig::entryCooldownSeconds`. El
valor por defecto del motor y de `LmRobot-H1.mq5` es `0`, por lo que la referencia
H1 se comporta exactamente igual que antes.

## Cómo se resuelve el TF

En `OnInit`:

```mql5
ENUM_TIMEFRAMES signalTimeframe =
   (SignalTimeframe == PERIOD_CURRENT ? _Period : SignalTimeframe);
ENUM_TIMEFRAMES atrTimeframe =
   (AtrTimeframe == PERIOD_CURRENT ? signalTimeframe : AtrTimeframe);
```

`signalTimeframe` se pasa a `g_market.Init`, `g_bars.Init` y
`g_metrics.Reset`. Por eso la instancia puede adjuntarse a un gráfico H1 y aun
así evaluar barras M1. El gráfico queda como superficie de operación y panel.

Para backtest conviene correr el Strategy Tester en M1 y con el mismo feed,
spread y capital que la corrida de referencia ([comparación justa](../comparacion-justa.md)).

## Pendiente de validación empírica

El perfil anterior es una **hipótesis razonada**, no una calibración medida. Al
cierre de esta edición no hay una cuenta MT5 válida conectada, así que no se pudo
correr el baseline M1. Antes de operar en real hay que:

1. Correr 2023 y 2024 completos en M1 con este perfil y exigir DD < 20 %.
2. Verificar que el resultado no depende de un solo mes ni de un solo símbolo.
3. Medir cuántas canastas abre por día y si `EntryCooldownSeconds=1800` corta
   demasiado el flujo o si sigue siendo excesivo.
4. Revisar el impacto del spread real en M1 (el tester con modelo "every
   tick" y spread flotante es más representativo que "open prices").
5. Ajustar `GridStepPips` y `TpPips` sólo después de ver la distribución de
   recorridos M1; con `TpPips=8` y spread `3` el coste es ~37 % del objetivo.

La decisión de fondo sigue abierta en
[DT-001 — Invariancia de riesgo y perfil entre timeframes](../deuda/DT-001-invariancia-timeframe.md).

## Deuda de estructura

El motor está compartido, pero el shell del EA (`OnInit`, `OnTick`, `OnTester`,
panel) está duplicado en los dos `.mq5`. Es aceptable para una sola variante. Si
aparecen más instancias, el paso siguiente es extraer ese shell a
`Include/LmRobot/App/ExpertShell.mqh` y dejar los `.mq5` como configuración fina.

## Convivencia

Si la referencia H1 y la instancia M1 corren a la vez en la misma cuenta:

- los `MagicNumber` deben ser distintos (ya lo son);
- el guard diario es por cuenta y lo comparten;
- el presupuesto agregado es por instancia, no por cuenta, así que el riesgo real
  se suma. Correr una sola instancia por símbolo o documentar el riesgo agregado.
