# Instancia M1

Variante de `LmRobot` que fija la señal, el RSI y el ATR en M1 sin depender del
timeframe del gráfico. Comparte todo el motor con `EA/LmRobot.mq5`: no hay una
copia de `Include/LmRobot`.

## Archivos

| Archivo | Rol |
|---|---|
| `EA/LmRobot.mq5` | Referencia H1/R11. No se modifica. |
| `EA/LmRobot-M1.mq5` | Instancia M1. Sólo cambia inputs y el TF de la señal. |
| `Include/LmRobot/**` | Motor único compartido por las dos instancias. |

## Compilar

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\build.ps1 -Source EA\LmRobot-M1.mq5
```

Salida esperada: `EA/LmRobot-M1.ex5` y `0 error(es), 0 warning(s)`.

## Diferencias con la referencia

| Aspecto | `LmRobot.mq5` | `LmRobot-M1.mq5` |
|---|---|---|
| TF de señal/RSI/barras | TF del gráfico | Input `SignalTimeframe`, por defecto `PERIOD_M1` |
| TF del ATR | `PERIOD_CURRENT` = TF del gráfico | `PERIOD_CURRENT` = `SignalTimeframe` (M1) |
| Etiqueta del backtest | TF del gráfico | `SignalTimeframe` (M1) |
| `MagicNumber` | `202611030` | `202611040` |
| Prefijo de log | `LmRobot:` | `LmRobot-M1:` |

La geometría de riesgo sigue siendo la de R11: `TpPips=8`, `GridStepPips=22`,
`SlPips=1000`, `MaxGridSteps=19`, `LotMultiplier=1.667`, `RiskPct=4.0`. No se
portó la tabla del refactor.

## Cómo se resuelve el TF

En `OnInit`:

```mql5
ENUM_TIMEFRAMES signalTimeframe =
   (SignalTimeframe == PERIOD_CURRENT ? _Period : SignalTimeframe);
ENUM_TIMEFRAMES atrTimeframe =
   (AtrTimeframe == PERIOD_CURRENT ? signalTimeframe : AtrTimeframe);
```

`signalTimeframe` se pasa a `g_market.Init`, `g_bars.Init` y
`g_metrics.Reset`. Por eso la instancia puede adjuntarse a un gráfico H1 y aun
así evaluar barras M1. El gráfico queda como superficie de operación y panel.

Para backtest conviene correr el Strategy Tester en M1 y con el mismo feed,
spread y capital que la corrida de referencia ([comparación justa](../comparacion-justa.md)).

## Pendiente de calibración

La instancia arranca con los defaults de R11 para tener una línea base. Antes de
tocar el perfil hay que medir:

- `MaxAtrPips=15` sobre M1 casi nunca bloquea; el filtro de volatilidad necesita
  otra calibración o un ATR anclado a H1.
- `MaxSpreadPips=100` es muy permisivo para un TP de 8 pips.
- `TpPips`, `GridStepPips`, `SlPips`, `MaxGridSteps`, `LotMultiplier` y `RiskPct`
  no se cambian sin una corrida base M1.
- La cadencia sigue siendo una evaluación por barra. Con la misma geometría, M1
  puede generar del orden de 60× más canastas por día que H1.

Esa decisión está abierta en
[DT-001 — Invariancia de riesgo y perfil entre timeframes](../deuda/DT-001-invariancia-timeframe.md).
No conviene implementar un "perfil M1" antes de definir si se ancla por operación
o por tiempo.

## Deuda de estructura

El motor está compartido, pero el shell del EA (`OnInit`, `OnTick`, `OnTester`,
panel) está duplicado en los dos `.mq5`. Es aceptable para una sola variante. Si
aparecen más instancias, el paso siguiente es extraer ese shell a
`Include/LmRobot/App/ExpertShell.mqh` y dejar los `.mq5` como configuración fina.

## Convivencia

Si la referencia H1 y la instancia M1 corren a la vez en la misma cuenta:

- los `MagicNumber` deben ser distintos (ya lo son);
- el guard diario es por cuenta y lo comparten;
- el presupuesto agregado es por instancia, no por cuenta, así que el riesgo real
  se suma. Correr una sola instancia por símbolo o documentar el riesgo agregado.
